# Настройка новых проектов GitHub и Codex

## Рекомендуемая схема

1. В проекте ChatGPT «Разработка» разместить общий регламент поведения (можно использовать содержание AGENTS.md, но без ненужного дублирования в каждом сообщении).
2. Создать отдельный репозиторий `project-starter`, добавить в его корень `AGENTS.md` и этот `PROJECT_SETUP.md`. Сделать репозиторий шаблоном: Settings → General → Template repository.
3. Создавать новые проекты через **Use this template → Create a new repository**. Файлы инструкции копируются в новый репозиторий при создании.
4. Для уже существующих репозиториев добавить `AGENTS.md` в корень один раз. Изменения шаблона не синхронизируются автоматически с ранее созданными репозиториями.
5. Для каждого нового проекта записать конкретные цели и ограничения отдельно (например, в `README.md`). Не превращать глобальную инструкцию в огромную энциклопедию.

## Реальная защита GitHub

- Включить правила защиты ветки `main`, если доступны на тарифе и для типа репозитория: запрет принудительной записи и удаления, требование pull request перед слиянием, нужные проверки.
- Учесть, что некоторые ограничения не доступны для частных репозиториев на бесплатном плане; проверить действующие возможности в Settings → Rules → Rulesets.
- Не включать обязательные проверки, которых нет: это может заблокировать слияние.
- Хранить независимые резервные копии важных проектов. История Git сама по себе не защищает от удаления репозитория.
- Учитывать: строгая защита `main` может потребовать изменить текущий способ прямой записи ChatGPT в репозиторий.

## Проверки без лишнего расхода

- Простая правка текста или CSS: только локальная проверка, если нет риска для логики.
- Изменение функции: относящиеся к ней тесты и связанные вызовы.
- Изменение архитектуры, общих интерфейсов или подготовка выпуска: расширенные проверки.
- Если автоматических тестов нет, не имитировать их наличие; явно попросить пользователя проверить конкретный сценарий в браузере.
- Повторять полный прогон после исправления только при достаточных основаниях.

## Важно

`AGENTS.md` — инструкция для агента, а не настройка разрешений GitHub. Файл-шаблон помогает с новыми репозиториями, но не обновляет старые. Реальная защита требует настройки GitHub отдельно.
